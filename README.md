    # Secure CI/CD Pipeline for Dockerized Applications

A Flask application packaged with Docker and protected by an automated
CI/CD workflow using **GitHub Actions** and **Trivy**.

## Project Overview

This project demonstrates how application testing, Docker image
creation, and container vulnerability scanning can be automated whenever
code is pushed to the `main` branch or a pull request targets `main`.

The pipeline aims to catch application test failures and fixable
high-severity security vulnerabilities before the Docker image is
accepted by the workflow.

## Objectives

-   Build and run a Flask application.
-   Write automated tests and execute them with Pytest.
-   Package the application into a Docker image.
-   Automate build and test activities with GitHub Actions.
-   Scan the Docker image for known vulnerabilities using Trivy.
-   Generate and upload a JSON security report.
-   Apply a security gate for fixable HIGH and CRITICAL vulnerabilities.

## Run the Application Locally

### 1. Clone the repository

``` bash
git clone https://github.com/harshskankariya/secure-cicd-project.git
cd secure-cicd-project
```

### 2. Create and activate a virtual environment (recommended)

On Windows PowerShell:

``` powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

``` bash
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install pytest
```

### 4. Run the tests

``` bash
pytest -v
```

### 5. Start the Flask application

``` bash
python app.py
```

Open `http://localhost:5000/` and `http://localhost:5000/health` in a
browser.

Stop the local server with `Ctrl+C`.

## Build and Run with Docker

Make sure Docker Desktop is running.

### Build the image

``` bash
docker build -t secure-cicd-app .
```

### Run the container

``` bash
docker run -d -p 5000:5000 --name secure-cicd-container secure-cicd-app
```

### Check the running container

``` bash
docker ps
```

### Stop and remove the container

``` bash
docker stop secure-cicd-container
docker rm secure-cicd-container
```

If the container name is already in use, remove the existing container
before creating another one.

## CI/CD Workflow

The workflow file is `.github/workflows/secure-pipeline.yml`.

It runs on: - Pushes to the `main` branch. - Pull requests targeting the
`main` branch.

The workflow stages are:

1.  **Checkout Source Code** --- retrieves the repository contents.
2.  **Set Up Python** --- configures Python 3.12 on the GitHub-hosted
    runner.
3.  **Install Dependencies** --- installs Python requirements and
    Pytest.
4.  **Run Pytest** --- executes the automated test suite.
5.  **Build Docker Image** --- builds `secure-cicd-app` using
    `docker build --pull --no-cache`.
6.  **Generate Trivy Report** --- scans the image and writes
    `trivy-report.json` to the GitHub Actions workspace.
7.  **Trivy Security Gate** --- checks HIGH and CRITICAL findings using
    `--ignore-unfixed`.
8.  **Upload Trivy Report** --- uploads the JSON report as the
    `trivy-security-report` artifact.

The workflow runs on `ubuntu-latest` and uses the GitHub Actions
permission `contents: read`.

## Understanding the Trivy Scan

Trivy identifies known vulnerabilities in software packages included in
the Docker image.

### Report generation

The report-generation step scans the image and saves the JSON output as
`trivy-report.json`.

### Security gate

The security-gate step uses:

``` bash
--severity HIGH,CRITICAL \
--ignore-unfixed \
--exit-code 1
```

-   `--severity HIGH,CRITICAL` selects HIGH and CRITICAL severity
    findings.
-   `--ignore-unfixed` excludes findings for which Trivy reports no
    available fix.
-   `--exit-code 1` makes the command return a failure exit code when
    matching findings are detected.

**Important:** `--ignore-unfixed` does not remove vulnerabilities from
the image or prove that the image is vulnerability-free. It changes
which findings cause this gate to fail. Unfixed findings can still
matter and should be reviewed. A successful workflow means the
configured checks passed; it does not mean the image contains zero
vulnerabilities.

## View the Trivy Report

1.  Open the repository on GitHub.
2.  Select **Actions**.
3.  Open the relevant workflow run.
4.  Scroll to the **Artifacts** section.
5.  Download `trivy-security-report`.
6.  Extract the archive and open `trivy-report.json`.

The JSON report contains scan metadata and vulnerability findings. The
optional `read_trivy_report.py` script can summarize the report locally,
provided it matches the report's structure.
